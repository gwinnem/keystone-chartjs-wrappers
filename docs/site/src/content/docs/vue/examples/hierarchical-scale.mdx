The `hierarchical` prop draws on a local port of
`chartjs-plugin-hierarchical`. Like [gradient](/vue/examples/gradient-plugin)
and [image label](/vue/examples/image-label-plugin), it isn't a
dependency on a third-party package at all — its logic is ported
directly into `keystone-chartjs-core`
(`src/hierarchicalScale.ts`). Boolean only, like `gradient`/`timestack`:
it registers a real, distinct `hierarchical` **scale** (not a Chart.js
"plugin" object) via this project's own `HierarchicalScale`, with no
plugin-level config of its own to merge here either. Use it by setting
`options.scales.<id>.type = 'hierarchical'`, which already reaches
Chart.js untouched via the existing `options` prop.

:::note[No external runtime dependency, unlike Timestack]
Unlike [Timestack](/vue/examples/timestack-scale) (which has a real,
hard `luxon` dependency for locale-aware time formatting), this scale
has zero runtime dependencies of its own — confirmed directly from the
real package's own `package.json` (only a `chart.js` peer dependency).
This port is therefore fully self-contained, the same outcome
`zoom`/`gradient`/`image label` already have.
:::

Being local code rather than a dynamic import also means this example is
genuinely live on this docs site, unlike the
[Timestack scale](/vue/examples/timestack-scale) example, which still
hits a docs-site build-pipeline gap around dynamic imports (its own real
`luxon` dependency currently can't be resolved the same way).

:::tip[A real, distinct tree-node data shape]
```js
data.labels = [
  { label: '2024', children: ['Q1', 'Q2', 'Q3', 'Q4'] },
];
dataset.data = [
  { value: 100, children: [20, 25, 22, 33] },
];
```
`label`/`children` on the labels side, `value`/`children` on the data
side — a real, distinct shape from the flat arrays every other kind or
plugin in this library accepts, confirmed directly from the real
package's own type declarations, dissected into this project's own
`HierarchicalRawLabelNode`/`HierarchicalValueNode` types (exported from
`keystone-chartjs-core`). See
[Plugins](/vue/api/plugins) for the full prop reference.
:::

:::tip[Click to explore the tree]
Click a collapsed category's own box below the axis to expand it, click
an expanded group's own box to collapse it back, or click the small dot
on a fully-expanded group to zoom in on just that branch — click again
on the zoomed-in view to zoom back out. All of this is real,
interactive `chart.data` mutation handled by this scale's own companion
plugin, not a separate example-only script.
:::
